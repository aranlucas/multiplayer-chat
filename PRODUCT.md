# Relay

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

Repository-evidenced audience: people collaborating on software with a coding agent, sharing a room from desktop or mobile. Primary-user segmentation beyond that remains unconfirmed.

## Product Purpose

Bring the whole room into the coding loop. Participants share an ordered OpenCode event stream and a repository workspace, steer an active turn or queue a follow-up, review permissions and diffs, and hand off an exact-commit preview or pull request.

## Positioning

One room owns the event history, agent session and repository workspace. People can see and shape the same work rather than exchange separate agent transcripts.

## Operating Context

A browser link joins a room. Maintainers configure the public repository and model, review tool permission requests and publish changes. Contributors participate within their existing authority. Local deterministic simulation supports demonstrations without live provider credentials.

## Capabilities and Constraints

Preserve the room protocol, role permissions, preview readiness and exact-commit handoff, GitHub publication, Steer/Queue semantics, reconnect behavior and participant-scoped drafts. Live services depend on configured Cloudflare, Railway, model-provider and GitHub access; local tests do not prove those services are available. No pricing, customer or performance evidence is established.

## Brand Commitments

The existing name is Relay. The user explicitly authorized an ambitious creative redesign while preserving core behavior and accessibility. No palette or typeface was made binding.
