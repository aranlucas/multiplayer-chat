# Cloudflare announcements reviewed for Relay

Reviewed on October 1, 2026. The review covers the 52 English-language posts in the [Cloudflare Blog](https://blog.cloudflare.com/) archive published September 1–October 1, 2026, including Birthday Week, plus the recent [Workers](https://developers.cloudflare.com/changelog/product/workers/), [Durable Objects](https://developers.cloudflare.com/changelog/product/durable-objects/), and [AI Gateway](https://developers.cloudflare.com/changelog/product/ai-gateway/) changelogs. Archive summaries were screened for relevance; the relevant announcements and API documentation were read in detail. Product fit and implementation choices below are assessments of this repository.

Relay already runs on Workers Static Assets, SQLite Durable Objects, the `cf` beta CLI, typed `cloudflare.config.ts`, Vite, Oxlint, and Oxfmt. Its sandbox uses Railway, its default model uses an OpenRouter free model, and its preview UI connects back to the original control-plane room.

Gateway integration uses the [OpenRouter provider-native endpoint](https://developers.cloudflare.com/ai-gateway/usage/providers/openrouter/) supported by the installed OpenCode SDK. It keeps `Authorization` for the OpenRouter key separate from `cf-aig-authorization` for the optional gateway Run token. The configuration validates account IDs, gateway slugs, token whitespace, the selected provider/model, and the payload logging option before use. Invalid configuration produces a health diagnostic and fails runner initialization instead of silently bypassing the gateway.

The default headers skip response caching, retain usage metadata, and exclude prompt/response bodies from logs. `CLOUDFLARE_AI_GATEWAY_LOG_PAYLOADS=true` enables payload storage explicitly. Traffic carries only `application=relay` metadata; participant-level spend attribution is not implemented. [User Insights](https://developers.cloudflare.com/ai-gateway/observability/user-insights/) groups unattributed traffic together, and content-based analysis may require additional logging settings. Routing remains off until a gateway ID is configured.

Issues and traces become active after deployment. Tracing is sampled because [trace spans share the Workers observability quota and billing](https://developers.cloudflare.com/workers/observability/traces/). Issues automations are configured separately in Cloudflare; this change only enables detection.

## Other announcements

The [cf CLI](https://blog.cloudflare.com/cloudflare-cf-cli-launch/), [Node-compatible module registry](https://blog.cloudflare.com/workers-module-registry-nodejs/), and [VoidZero tooling](https://blog.cloudflare.com/voidzero-update/) already align with this repo's current stack. There is no reason to migrate the React SPA to Vinext, Python Workers, Rust Workers, EmDash, or a managed Cloudflare OS workspace for these changes.

KV Instant, K2 streams, Basin, and AI Search address workloads Relay does not currently need: globally replicated configuration, large event ingestion, analytical data lakes, and managed search. SQLite Durable Objects already provide ordered room events and persistence. Adding another store would introduce coordination and consistency work.

Browser Run/Kitesurf, Forge, and BEACON could support future browser tools, API generation, or performance research. This review does not add product behavior just to consume a new service. Registrar, monetization/payment products, publisher controls, enterprise network/security products, certificate infrastructure, and Cloudflare's operational/corporate updates have no direct repository change to apply here. Turnstile and application security profiles merit a separate abuse-control design for public live rooms, with an explicit participation flow.

## Verification

Provider tests cover unchanged direct routing, gateway authentication, explicit payload logging, rejected configuration, and missing provider credentials. A Workerd integration test uses the installed OpenCode SDK to construct two concurrent model requests and checks their exact URL and headers before network dispatch. This verifies the SDK integration without paid inference or production mutations.

`pnpm lint`, `pnpm format:check`, `pnpm typecheck`, `pnpm test`, and `pnpm build` passed; the suite contains 146 tests across 25 files. `pnpm exec cf deploy --prebuilt --dry-run` also passed, and the generated Worker configuration contains the requested Issues, trace sampling, and query redaction settings. The build exited successfully while emitting dependency `eval` warnings and a missing local Docker daemon message.

No live deployment was made. External gateway availability and dashboard ingestion require a configured live environment. This change does not alter room events, reconnect logic, workspace publication, or preview handoff.
