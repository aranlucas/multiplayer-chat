## Why plan 001 was shipped

This is a substantial correctness bug in the feature the repo exists for: hand off a finished change as a pull request. The room publishes every new revision to its saved pull request and never checks whether that PR is still open. Once a maintainer merges it and GitHub auto-deletes the branch, the ref read throws `Not Found`. Live turns await `publishSavedPullRequest()` (`src/server/agent-room-core.ts:1417`), so every later _successful_ agent turn is reported as `Agent turn failed: Not Found`. When the branch survives, revisions are pushed silently into a closed PR. The client can't recover, because `handlePullRequest` (`src/client/app.tsx:152`) only reopens the old URL. The fix stays inside the GitHub client and the room's event text, and the repo's own Vitest fakes of the GitHub REST API can verify it completely.

## Findings considered and rejected

- Role checks missing on `question.reply`, `agent.pause` and brief review: roles are query-selected by design (see `docs/reliability-audit.md`, "Rejected hypotheses"). They are not an authorization boundary.
- `handoffCors` reflects any Origin: no credentials are allowed, and tickets are hashed, origin-bound, one-use and expire after 60 s.
- `/local-preview` hostname gate: Workers routes by zone hostname, and the route is enabled only in simulation mode or on loopback.
- `pnpm audit` high advisory for `minimatch` (only through `@opencode/sdk > @opencode/util > @npmcli/*`): it's on a config-loading path that takes no user-controlled globs. Leave it to Dependabot.
- Permission replies aren't forwarded to the OpenCode runner (`replyToPermission` only updates SQLite). The live config is allow-all with `execute` denied (`src/server/opencode.ts:175-178`), so OpenCode never asks and no turn can hang. Investigate only if an `ask` rule is ever added.
